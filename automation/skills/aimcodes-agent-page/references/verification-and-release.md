# 正式构建与线上验收

## 本地

使用仓库正式构建和预览服务器，所有内部操作带 `?qa=1`。至少桌面约1440px与手机约390px；遇到问题扩查。逐项对照用户指定模板：

- 品牌导航／Logo／语言选择／面包屑；H1 的实际字号、位置、内容宽度与模块完整性。
- 技能图标和本地化名称正确；每个视频真正播放、时间推进，比例／控件与模板相符；没有重复副标题、价格和制作说明。
- 首图桌面和手机裁切；图集填满、人物清楚、点击放大、关闭／Esc、焦点返回；无来源文字叠图。
- 1×／5×真实 Canvas、地图切换、成功复制反馈；记录实际写入的代码并与编辑器实际生成值逐字比较。入口目标和语种正确。
- 五语切换、窄屏溢出、悬停、键盘 focus-visible 与触屏布局。
- 在同一浏览器先后打开当前英雄、模板与另一个英雄；通过真实站内入口再进入新页。读取计算颜色，不能只看样式文本。把实际共享 CSS 临时追加到文档样式末尾后再检查标题、正文、按钮、边框、悬停和焦点。临时验收样式不写入产品。
- 主题选择器需要高于共享样式的优先级，不能靠 import 顺序。例如 `.hush-page.{agent}-page …`；按钮／焦点、正文／标题、灯箱和控件都要覆盖。不要全局替换模板色值。
- 静态 HTML 与 React 对齐；各语言 canonical／robots／hreflang、Sitemap 和图片 Sitemap 符合本次决策。noindex 页面不能进入 hreflang。

机械校验不能证明事实、画面与交互正确。发现模板已有无关缺陷先记录，不顺手改；若直接阻碍当前任务的完整功能，则把必要修复纳入本次范围并解释。

## 发布

只有当前任务明确批准发布才继续。核对远端 `main`、当前正式域名 `build-meta.json`、托管配置、CI 和最近 PR 状态；现有平台可能与文档不同，不自动迁移平台。

说明准确变更范围和回滚边界。只暂存当前任务的源码、派生素材、验证及必要来源清单，不上传账号报表、原始大视频、私人上下文、依赖、构建产物或凭据。提交前跑完整检查并核对列表。

通过 PR 发布，等实际 GitHub 检查及当前平台预览。预览需实际打开新英雄页及未改变的模板，测主题、媒体、复制、编辑器和索引；不能把绿色状态当预览验收。用户已授权发布时完成合并和部署，无需重复确认同一步。

合并后验证正式域名：构建提交匹配 `main`，新页和媒体 HTTP 正常，五语标题／robots／canonical，Sitemap 与 hreflang、桌面／手机、交互和跨英雄颜色。记录正式 URL、PR、部署版本、数量和仍未验证的事情。回滚使用合并前提交的恢复 PR 或平台已知部署版本，不覆盖工作树中的其他任务内容。

不要把中文可访问称中文 SEO 上线；不要把页面可索引称已收录；不要把发布称流量增长。GSC／GA4 以完整周期按记录的窗口复查，不自动创建监控或新任务。
