# AimCodes 首笔真实付款优化规划

状态：第一项优化已发布，待观察
日期：2026-09-17
目标：在不降低免费准星核心体验的前提下，验证首笔真实付款，并建立可重复优化的 GMV 漏斗。

实施记录（2026-09-17）：PR #74 已合并到 `main`（`70fb484`）并由 Netlify 生产部署完成。复制代码这一最高意图行为不再受 8 秒停留门槛限制；提示仍等待复制反馈结束才显示，并保留每会话一次、关闭后抑制与手机紧凑入口。同步更新五语种结果页付费价值表达，明确 5 个槽位对应不同对枪场景而非随机变体。发布前 `pnpm check:release` 24/24 通过；Ego Lite 已复验线上复制后引导、反应测试结果页付费价值说明，以及无横向溢出。支付、Whop 设置、权益逻辑、路由和索引范围均未改变。

## 1. 本次结论

AimCodes 的付费交付链路已经具备上线条件：用户完成三轮反应测试、选择偏好、进入 Whop 一次性结账；付款成功由签名校验的 `payment.succeeded` 回调确认，随后即时获得 5 款个人准星、两次重新生成和长期访问。

当前没有真实转化，不能直接判断是价格、产品价值、支付体验还是流量质量的问题。第一阶段不应继续增加付费功能，而应先让每一个流失节点可观测，并以一笔由独立买家完成的生产订单验证端到端真实支付。

## 2. 事实、假设与非目标

### 已确认事实

- 产品为一次性 `AimCodes Crosshair Pack`，价格 USD 1.99。
- 交付为 5 款个人准星、地图预览、完整代码、长期访问、2 次重新生成与 3 个历史版本。
- Whop Sandbox 已完成端到端付款、Webhook、交付与手机端验证；尚未执行真实生产付款。
- 最近 28 天 Google 自然搜索活跃用户约 1,001；反应测试页停留时长在主要自然落地页中最高，约 2 分钟。
- 最近一个完整 GSC 对比周期，站点点击下降约 35%；其中 Funny 准星页点击从 89 降至 32，但排名与 CTR 未明显恶化，主要是展示量下降。
- 现有“关键事件”不能等同于收入：必须单独核验 Whop 的成功付款与 GA4 的 `purchase`。

### 待验证假设

1. 反应测试完成用户比普通目录用户更愿意购买个人方案。
2. 用户对“为什么这个方案适合我”的理解不足，是付费页点击低于预期的主要原因之一。
3. USD 1.99 是足够低摩擦的首发价格；在没有基线前不应频繁调价。
4. 独立用户的真实付款可用于同时验证支付、Webhook、交付、GA4 归因与客服找回流程。

### 本阶段非目标

- 不以广告展示作为首要收入手段。
- 不开发订阅、账户体系、复杂装备商城或职业选手装备分佣页。
- 不在准星复制、地图预览等主操作中插入强制付费墙。
- 不因为短期流量回落继续大量新增相似 SEO 页面。

## 3. 北极星指标与护栏

### 北极星指标

每周“已验证 GMV”：仅计入 Whop `payment.succeeded` 且价格、币种、订单和权益校验全部通过的订单金额。

### 核心漏斗

```text
高意图行为
→ 浮窗曝光
→ 反应测试开始
→ 三轮测试完成
→ 个人方案曝光
→ 偏好选择完成
→ Whop 结账打开
→ Whop 支付成功
→ 私人方案交付页访问
→ 首次复制代码
```

### 质量护栏

| 指标 | 目的 | 不可接受信号 |
| --- | --- | --- |
| 准星代码复制成功率 | 保护免费核心价值 | 付费入口导致复制或导入主路径下降 |
| 测试完成率 | 判断测试是否仍有吸引力 | 引入付费文案后完成率明显下降 |
| 付款成功后交付成功率 | 保护信任 | 成功付款未进入交付页，或权益未创建 |
| 支付后首复制率 | 验证交付被实际使用 | 付款后用户未复制任何代码 |
| 退款、拒付、支持请求 | 验证价值与预期一致 | 主要问题集中在“以为会获得别的内容” |

## 4. 数据实施要求（P0）

### 4.1 统一事件口径

保留已有事件，并在不采集个人信息、搜索词或完整来源 URL 的前提下，将下列事件建立成可串联漏斗：

| 阶段 | 推荐事件 | 必需参数 |
| --- | --- | --- |
| 浮窗 | `finder_nudge_view`、`finder_nudge_click`、`finder_nudge_dismiss` | `finder_entry`、页面类型、语言 |
| 测试 | `finder_start`、`finder_round_complete`、`finder_result_view` | `finder_entry`、反应段位、尝试结果 |
| 方案 | `aim_pack_offer_view`、`aim_pack_preferences_complete`、`aim_pack_checkout_start` | 方案版本、模式、视觉偏好、语言 |
| 支付 | `purchase` | 唯一交易 ID、`value=1.99`、`currency=USD`、产品 ID |
| 交付 | `aim_pack_delivery_view`、`aim_pack_first_code_copy`、`aim_pack_regenerate` | 订单匿名标识、剩余重生成次数 |

`purchase` 只能由 Whop 成功付款回调触发。前端打开 Whop、返回站点或页面加载都不能记为付款成功。交易 ID 必须去重，避免 Webhook 重试造成 GMV 重复。

### 4.2 报表

建立一个仅供内部使用的“GMV 漏斗”报告，按以下维度拆分：

- 日期；
- 首次着陆页类型（Funny、普通集合、详情、反应测试、首页）；
- 语言（优先英语、日语）；
- `finder_entry`（`nudge` / `direct`）；
- 自然搜索、社媒、直接访问；
- 方案版本与价格。

GMV 报表必须同时展示：Whop 成功订单数、Whop 毛 GMV、GA4 `purchase` 数、两者的差异。Whop 是付款事实源，GA4 只用于归因与行为分析。

## 5. 用户路径优化

### 5.1 获客页：不硬卖，建立下一步理由

Funny、Dot、Small 等搜索落地页的首要任务仍是帮助用户找到并复制准星。只在用户完成高意图操作后展示轻量入口：

> 不确定哪种更适合你？完成 3 轮反应测试，看看你的瞄准风格。

规则：至少停留、滚动或完成筛选/复制后才出现；每会话一次；关闭后按既有抑制周期执行。避免首次加载弹窗、遮挡卡片、强制中断复制。

### 5.2 测试中：保持纯粹，不提前售卖

三轮测试只服务于完成测试。进度、规则、反馈和减少动态效果偏好优先；不展示价格、折扣倒计时或中途付费提示。

### 5.3 测试完成：先给真实免费价值，再售卖差异化结果

结果页按以下顺序呈现：

1. 成绩、段位、稳定性和一条真实的瞄准风格洞察；
2. 解释“个人方案会额外获得什么”：5 个不同用途的候选、地图预览、完整可复制代码、按偏好生成、2 次重新生成、长期访问；
3. 只展示不对应真实交付的通用示例，不泄露可复制的完整个人结果；
4. 主按钮使用明确文案：`解锁我的 5 款准星包 — $1.99`；
5. 在按钮附近简短说明：一次性付款、即时交付、长期访问、需要帮助请联系 `contact@aimcodes.com`。

禁止使用虚假库存、伪倒计时、未经验证的用户评价或夸大“提升枪法”的承诺。

### 5.4 付款页：消除最后一公里的疑虑

进入 Whop 前，站内确认页只保留：产品名称、交付清单、总价 USD 1.99、长期访问、退款政策链接和支持邮箱。不要要求注册站内账户，不要在此处加入额外问卷。

支付页应优先保持 Whop 的受信任结账流程。价格、交付范围和退款条款必须与站内入口完全一致；付款失败时保留用户选择并给出重试或联系客服的清晰路径。减少步骤、明确总价、可见支持与退款信息、无强制注册是结账转化的基础实践。[Stripe 的结账设计建议](https://stripe.com/resources/more/checkout-screen-best-practices)

### 5.5 交付页：把购买转化为使用与口碑

付款成功后立即展示可用方案，不依赖邮件；邮件只作为找回与售后补充。交付页第一屏应包含：

- “你的方案已解锁”的明确确认；
- 第一款推荐准星的地图预览与复制按钮；
- 剩余 4 款的用途区分；
- 两次重新生成额度；
- 付款/交付异常时的订单恢复和 `contact@aimcodes.com` 支持入口。

首次复制成功后再邀请分享挑战或回到免费目录，不能打断领取代码。

## 6. 14 天实验计划

### 第 0 天：生产就绪核验

- 由独立买家完成一笔 USD 1.99 生产订单；商家本人不自购。
- 核验 Whop 成功付款、Webhook 签名、权益创建、即时交付、首次复制、订单找回与 GA4 `purchase`。
- 将订单事实与 GA4 事件按匿名订单标识核对；若存在差异，先修正归因，不开始文案或定价实验。

### 第 1–7 天：只观察，不改价格

- 保持 USD 1.99 与一个主付费方案；
- 每天检查付款失败、Webhook 失败、交付失败与支持请求；
- 每 48 小时审阅漏斗分层，避免对极小样本作出页面结论；
- 记录最高意图来源页和语言，不将“关键事件”误读为订单。

### 第 8–14 天：基于丢失位置做一个单变量实验

| 发现 | 优先实验 | 不要做 |
| --- | --- | --- |
| 完成测试多、方案曝光低 | 调整结果页信息层级与主按钮位置 | 同时改价格、产品和文案 |
| 方案曝光多、结账开启低 | 用具体交付物替换抽象卖点 | 增加催促弹窗或假稀缺 |
| 结账开启多、支付成功低 | 审核价格透明度、Whop 可用支付方式、错误提示与信任信息 | 把失败直接归咎于价格 |
| 支付成功但交付使用低 | 优化交付首屏与复制引导 | 继续引流到旧结果页 |

每次只改一个变量；实验最少覆盖一个完整的 7 天周期，除非出现支付或交付故障。

## 7. 第二阶段收入扩展（首笔付款稳定后）

### 优先级 1：升级包，而非新增无关品类

若 USD 1.99 的付费意愿被验证，再测试 USD 4.99 的升级包。升级必须是可感知且真实可交付的增量，例如按枪械/场景组织的方案、第二套备选风格、训练节奏与更丰富的地图演示；不能只是将免费目录中的代码重新打包。

### 优先级 2：谨慎的联盟分佣

只在反应测试结果页的低干扰位置或独立装备内容页尝试；不放在复制代码和付款主路径旁。任何型号、价格与可购性必须有可靠来源与检查日期。联盟关系在链接旁明确披露，披露应靠近触发推荐或购买决定的位置。[FTC 数字广告披露指引](https://www.ftc.gov/sites/default/files/attachments/press-releases/ftc-staff-revises-online-advertising-disclosure-guidelines/130312dotcomdisclosures.pdf?link=external)

### 暂缓：广告

在当前流量与付费漏斗尚未验证时，展示广告的预计收入有限，且会损害反应测试与付款路径的注意力。若未来接入，仅限低交互攻略内容中的手动广告位，并排除测试、复制、交付与支付页面。

## 8. 成功与停止条件

### 本阶段成功条件

1. 独立买家完成至少一笔真实生产付款；
2. Whop、权益、交付与 GA4 `purchase` 均可一一核对；
3. 能明确判断用户主要流失在“方案曝光、结账开启、支付成功”中的哪一环；
4. 免费复制与测试完成等核心体验指标未因付费入口而明显退化。

### 应暂停并修复的条件

- 付款成功后没有即时交付；
- Webhook 重试造成重复权益或重复 GMV；
- GMV 与 Whop 成功订单无法核对；
- 用户误以为购买的是外挂、游戏内货币或“保证提升”；
- 付费入口明显妨碍免费用户复制、测试或分享。

## 9. 实施顺序与责任边界

| 顺序 | 工作 | 风险 | 验收 |
| --- | --- | --- | --- |
| P0 | 生产订单与支付/交付/归因全链路核验 | 高 | 独立订单可在 Whop、权益和 GA4 中核对 |
| P1 | GMV 漏斗报表与事件去重 | 中 | 每一层可按来源、语言和落地页查看 |
| P2 | 结果页价值表达与 CTA 单变量实验 | 中 | 完成到结账开启率可比较 |
| P3 | 交付页首次复制与找回体验优化 | 低 | 已付款用户可立即领取并使用 |
| P4 | USD 4.99 升级包或联盟试点 | 中 | 仅在首发方案价值被验证后启动 |

本文件记录本轮转化入口的发布事实，不代表付款、价格、Whop 设置、GA4 设置或支付权益逻辑已经改变。任何生产支付测试、GA4 事件改动、定价改动或上线操作都需要单独确认并遵循项目发布流程。
