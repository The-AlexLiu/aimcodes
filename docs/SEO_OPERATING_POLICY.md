# AimCodes SEO 运营规则

最后更新：2026-09-11

## 目标

用较少、意图清晰且可完成真实任务的页面获取搜索流量。产品界面支持范围与 SEO 索引范围分开管理，避免为了语言数量或近义词数量制造重复页面。

## 语言分层

| 语言 | 产品界面 | SEO 状态 | 新增内容规则 |
| --- | --- | --- | --- |
| 英语 `en` | 完整保留 | 增长 | 可依据 GSC、GA4、趋势与竞对缺口新增 |
| 日语 `ja` | 完整保留 | 增长 | 可依据日本已有排名和本地查询新增 |
| 西班牙语 `es` | 完整保留 | 维护 | 保护已有 URL；没有明确数据不扩页 |
| 巴西葡萄牙语 `pt-BR` | 完整保留 | 维护 | 保护已有赢家；没有明确数据不扩页 |
| 简体中文 `zh-CN` | 完整保留 | 产品专用 | 首页、准星库、反应测试可索引；其他页面 `noindex,follow`，不新增中文 SEO 页 |

`noindex` 会让对应 URL 逐步退出搜索结果，因此这些 URL 自身的自然流量会下降。它不会阻止用户直接访问，也不删除界面；`follow` 允许搜索引擎继续发现页面中的链接。执行收缩时必须先保护已有赢家，不得把已有有效流量的 URL 一刀切。

## 新页面搜索意图门

任何新建并索引的集合页、指南页或工具页都必须先回答：

1. 目标查询是什么，数据或外部证据在哪里？
2. 站内最接近的现有 URL 是什么？
3. 新页面帮助用户完成的任务与现有页有何不同？
4. 页面具有什么独有数据、交互、示例或可复制结果？
5. 哪些语言应被索引，为什么？
6. 预期用 GA4/GSC 的什么指标、在什么观察周期判断保留或合并？

以下情况默认不索引：仅替换近义词；素材集合高度重叠；正文只是模板改写；没有至少一个独有任务或交互；没有清楚的数据来源。无法证明独立意图时，优先扩充已有页面。

## 当前收缩决定

- `meme-crosshairs` 与 `funny-crosshairs` 内容完全重叠，前者永久重定向至 Funny，停止独立发现和索引。
- `pro-players` 与 `pro-player-crosshairs` 聚合入口退出产品和 SEO，永久重定向至准星库。
- 职业人物简介、头像资料和未来外设展示不再出现在具体准星页。
- TenZ、Aspas 等已有具体准星代码页继续保留：它们已有搜索表现，并且满足“预览、测试、复制代码”的独立用户任务。
- 社媒每日三平台各 3 条的工作流不属于本轮收缩范围。

## 发布与复查

- 路由或索引变化必须运行 `pnpm validate:seo-scope`、`pnpm check:release`，并审核 `.aimcodes-reports/current/seo-scope.md`。
- 发布后用等长完整周期对比 GSC 的有效索引页、点击、展示、CTR 与查询分散度；GA4 同时看自然搜索落地会话、互动率和关键操作。
- 旧 URL 必须保留永久重定向，不用 404 替代；Sitemap 和 hreflang 只能声明允许索引的 URL。
- 首轮观察至少 21–30 天。若被收缩页面原有查询转移至主页面且总点击不下降，继续保持；若出现明确损失，先检查重定向、意图承接与主页面内容，不直接恢复整批模板页。
