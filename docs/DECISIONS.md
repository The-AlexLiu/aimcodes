# AimCodes 技术与产品决策记录

最后更新：2026-08-10

## D-001：GitHub 是唯一项目事实来源

**状态：已接受**

代码、规则、架构、任务和交接结果以 GitHub 中可审查的文件、Issue、提交和 PR 为准。GPT/Codex 与 Cursor 的聊天记录不能作为唯一依据。

原因：聊天记忆无法可靠跨工具同步，且难以审查、回滚和多人协作。

## D-002：根目录 `AGENTS.md` 作为共享智能体规则

**状态：已接受**

GPT/Codex 与 Cursor 都先读取根目录 `AGENTS.md`。项目特定规则记录在 `AGENTS.md` 中，不得相互复制或覆盖核心事实。

原因：避免两个工具形成两套冲突的项目记忆。

## D-003：保持无后端的静态工具架构

**状态：已接受**

在没有明确业务需求前，AimCodes 继续使用 React + Vite + Netlify 静态部署，不引入登录、数据库或自建 API。

原因：当前产品核心功能可在前端完成，静态架构交付轻、成本低、维护简单。

## D-004：固定四语种目录路由

**状态：已接受**

正式语言路径固定为 `/en/`、`/es/`、`/pt-br/`、`/zh-cn/`。旧 `?lang=` 链接只作为兼容入口，不作为 canonical。

原因：便于 Google 独立抓取、配置 hreflang、衡量各语言增长。

## D-005：反应测试只推荐一个准星

**状态：已接受**

结果页不展示多个候选项；根据三轮速度、稳定性和提前点击返回一个首选准星，并允许当场预览、换色、复制和分享。

原因：减少选择负担，让“帮我选”真正完成选择。

## D-006：准星颜色必须改写最终代码

**状态：已接受**

颜色选择不仅改变 Canvas 预览，还必须通过解析器更新用户最终复制的无畏契约代码。

原因：避免预览与实际导入结果不一致。

## D-007：GA4 不采集原始搜索词

**状态：已接受**

`search_used` 只发送 `query_length`、`results_count` 和 `has_results`。

原因：工具不需要收集用户输入原文，减少潜在个人信息和无关数据进入 GA4。

## D-008：生产发布需要人工授权或受保护的 `main`

**状态：已接受，已落地**

生产流程固定为：功能分支提交 PR，GitHub 校验与 Netlify Deploy Preview 通过后由人工或明确获授权的智能体合并 `main`，Netlify 自动发布。任何工具都不得默认执行手动生产部署。

原因：避免 Cursor、GPT/Codex 或本地脏工作树直接覆盖正式站。

## D-009：主站渲染器是当前发布基准

**状态：临时接受**

在单一源重构前，以 `public/tools/social-renderer/index.html` 作为产品发布基准，独立仓库为作品集镜像，`output/` 为本地历史副本。

原因：三份 HTML 同时人工维护容易分叉；需要先明确编辑方向，再实现自动同步。

## D-010：产品文案使用玩家语言

**状态：已接受**

用户界面保持直接、自然、轻挑衅感，不用后台术语、过度免责或无必要解释。四语种根据当地表达重写，不逐字翻译。

原因：AimCodes 是 C 端游戏工具，不是企业后台或研究报告。

## D-011：只索引具备独立价值的 SEO 页面

**状态：已接受**

准星详情即使可以批量生成，也只有在代码有效、搜索意图明确、四语种文案完整、存在独立选型说明并被主题集合链接时才进入 sitemap。其他详情保持 `noindex,follow`。

原因：新站需要控制重复薄页和无效抓取，页面数量不能替代真实用户价值。

## D-012：内容只扩展准星任务，不做泛游戏资讯

**状态：已接受**

新增内容优先覆盖选准星、看参数、换颜色、导入、复制和排错等明确任务，并把用户继续带入预览、换色和复制流程。赛事新闻、泛英雄攻略和无更新机制的海量选手页不作为当前 SEO 主线。

原因：AimCodes 的优势是准星数据和交互工具。围绕现有能力建立主题权威，比追逐泛游戏流量更容易形成稳定排名，也更能转化为代码复制和回访。

## D-013：AdSense 采用手动广告位与页面白名单

**状态：已接受**

未来广告只允许出现在首页、目录、集合、知识文章、导入指南和重点准星详情页。反应测试、404、关于/隐私/条款/联系页、非重点薄内容详情和素材渲染器默认不可投放。即使页面在白名单中，广告也不得靠近复制、导入、分享、随机选择或其他交互按钮。

原因：AimCodes 的核心操作密集，Auto Ads 容易把广告插入游戏测试和产品按钮附近，增加误触与 Google 发布商政策风险。手动广告位更适合控制内容距离和用户体验。

## D-014：信任页面与 SEO 索引分离

**状态：已接受**

四语种关于/审核方法页允许索引；隐私、条款和联系页保持公开可访问并由页脚链接，但使用 `noindex,follow` 且不进入 sitemap。

原因：审核所需的主体、隐私、权利和联系信息必须可访问；但政策页和联系页搜索价值有限，不应为了增加页面数量进入索引。关于与审核方法页具有独立产品价值，可以作为品牌与内容质量信号。
